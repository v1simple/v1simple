# Bench Investigator V1 Result Ledger

This is the requested compact record of facts that changed the implementation
and results that demonstrate the tool. It has no approvals, owners, gates, or
pending-state checklist. Investigation findings remain in each run's
`investigation.json`.

| Stage | Result or evidence | Direct consequence |
|---|---|---|
| Evidence audit | Existing artifacts had no shared causal ID or exact host↔DUT clock mapping; replay recorded requests rather than delivery; display commits omitted some semantic render inputs. | The implementation adds the minimum joined causal trace, bounded clock observations, and render inputs needed for timing and call investigation. |
| Camera interpretation | Owning camera code used parser-derived encounter values as expected display values. | Camera grades are leads only; findings must compare independent stimulus, raw video, and code. |
| Prior-tool removal | The removed validators and static detectors were not invoked by `bench.sh`, did not inspect code or logs semantically, and emitted empty code references. | V1 keeps a thin model-led runner and proves value with findings rather than detector catalogs. |
| Design correction | The first draft preselected replay transitions, retained mandatory transcripts, lacked coverage/source-basis fields, and could force unsupported cause claims. | V1 retains no transcript content, makes video review iterative and model-led, and requires coverage, source basis, uncertainty, and resolvable selectors. |
| Runtime capability | Local inspection confirmed read-only ephemeral model execution, strict JSON output, image input, local-provider selection, and generic video extraction. | V1 uses concrete installed tools instead of adding a provider framework. |
| Runner smoke | A synthetic smoke exercised structured output, image attachment, repository search, and a follow-up pass. | The runner protocol works; the selected production model and a real semantic result remain separate claims. |
| Runner delivery | The runner, strict JSON Schema, and evidence-first prompt provide atomic output, source attribution, resolvable selectors, bounded iterative video requests, and honest partial/failure reports. `bench.sh` invokes an explicit local provider after scoring without changing the scorer's exit status; hosted execution requires a separate direct `--hosted` command. | V1 produces replaceable evidence documents, not a verdict, gate, ownership system, or detector catalog. Focused runner tests passed. |
| Video evidence | The helper performs a bounded full-frame temporal scan, overview sampling, and model-requested interval extraction. It uses no fixed ROI, color threshold, reference image, recognizer, or expected transition catalog; regular sampled points are summarized by count/bounds/cadence while abnormal and edge gaps retain bounded locations. | Candidate selection follows a changed scenario, while semantic correctness remains the model's decision using stimulus, trace, code, and frames. Focused video tests passed. |
| Causal evidence | Replay, host, camera, and firmware preserve scenario content identity, notification request and transport-acceptance identities, host monotonic events, bounded host↔DUT clock observations, runtime image identity, exact-session causal stages, parser/state/alert revisions, renderer commits, payload digests, and loss counters. External scenarios may be irregular or fractional without changing the investigator. | The model can trace a displayed value from authored stimulus through host send, DUT receive/parse/publish, render decision, and camera PTS while stating remaining clock and delivery uncertainty. |
| Independent review | Reviews corrected malformed-output crashes, stale-source attribution, ambiguous image ordering, unsupported primary citations, non-unique clock mappings, private-path leakage, overclaimed video coverage/PTS, unbounded cross-video extraction, framing-loss visibility, and a display-to-encounter digest mismatch. | Bad evidence now fails locally and narrowly instead of manufacturing confidence or discarding unrelated findings. |
| Initial connected run | A complete camera/trace corpus exposed four support-tool defects: runtime identity used the wrong hash length, valid zero-alert END rows were rejected, one bounded pre-start status exchange was rejected, and mid-run source drift left no current camera grade. Each cause was fixed with a focused regression. | Real hardware evidence improved the tool and scorer rather than being hidden behind an artifact gate. The captured run remained unchanged. |
| Frozen connected run | A later code-frozen run returned bench, collection, replay, and camera `PASS`. It recorded 828 stimuli, 5,939 causal rows with zero source/trace loss, 797 encounter rows, 1,086 contiguous renderer commits with zero drops, and a 337-second, 67,281-frame video with zero recorder drops or timing anomalies. The local firmware ELF digest matched the DUT-reported runtime image identity. | The evidence pipeline works on a connected DUT/camera with a changing replay, while the ordinary bench result remains independent of investigation. |
| Causal join audit | An independent join resolved all 1,594 encounter provenance references and 2,133 of 2,134 current-session display references. One early display commit inherited a pre-start state event missing from the session trace, exposing a falsely session-stamped boundary reference. | Firmware now emits explicit retained state/alert baselines with the original RX identity and the start boundary as observation time. Focused tests passed 9/9 and the production build succeeded; unmatched retained alert contents remain unknown. |
| Backend failure evidence | A frozen run automatically wrote a schema-valid `investigation.json` after discovering 50 artifacts with a deliberately failing backend. All artifacts were honestly marked skipped and the report recorded failed execution, unavailable source, and zero findings. | Failure behavior is proven and non-gating. Hosted analysis remains a separate explicit opt-in. |
| Local semantic investigation | The cloud-disabled default vision model completed the bounded two-pass flow on frozen connected evidence in just under an hour. It covered three artifacts, one owning-code location, one clock mapping, and one requested video interval. It claimed zero actionable findings and preserved three primary-citation-invalid leads as schema-valid unresolved items containing evidence, code, ranked hypotheses, and a next observation. Further video requests exceeded the bounded image reserve, so the report remained partial. | The automatic local path is proven on real multimodal evidence without overstating model quality. The current small model can produce useful follow-up leads, but citation precision and runtime are the next quality targets. |
| Integrated verification | The final full repository suite passed, including privacy setup, host/replay/camera tests, native and sanitizer suites, frontend checks, and production firmware/LittleFS artifacts. Production firmware used 25.2% RAM and 15.5% flash. | The implementation and production build are verified together; this does not substitute for separately recorded live hardware evidence. |

Rows record only implemented capabilities, observed defects, verified fixes, or
